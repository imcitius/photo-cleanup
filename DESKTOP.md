# Настольное приложение на Tauri v2

Рабочий документ разработки. Состояние на 21.09.2026, база — версия 0.2.15.
В публичную часть репозитория не предназначен.

## Зачем

Сейчас на Windows продукт раздаётся как zip с exe и батником: распакуй,
запусти батник, он поднимет сервер и откроет браузер. Дальше интерфейс
живёт вкладкой, которую надо не потерять, и закладкой, которую надо
завести. Для инструмента, которым разбирают архив неделями, это неудобно.

Нужно окно приложения: своя иконка на панели задач, запуск двойным
кликом, понятное «оно запущено» и «оно выключено», и обновление без
ручного скачивания.

macOS получает то же самое почти бесплатно — тот же код, другой упаковщик.

## Что это не меняет

- Сервер, база, миниатюры, вся логика — остаются как есть. Десктоп это
  окно поверх того же `pc-api`, а не вторая реализация.
- Docker-образ и CLI никуда не деваются: на NAS нужен сервер, а не окно.
- Никаких сетевых вызовов не добавляется, кроме проверки обновлений — и
  та выключается настройкой.

## Устройство

Новый крейт `crates/pc-desktop` — отдельный бинарь. Он поднимает
существующий сервер на `127.0.0.1` со случайным свободным портом и
открывает окно на этот адрес.

Почему отдельный крейт, а не флаг: на Linux вебвью тянет `webkit2gtk`, а
образ собирается `FROM scratch`. Крейт исключается из `default-members`
корневого `Cargo.toml` и собирается явно только в маковой и виндовой
джобах; `cargo test --workspace` на ubuntu его не трогает.

Требуется одна правка в `pc-api`: сейчас `serve()` сам биндит адрес и
ничего не возвращает. Нужен вариант, отдающий занятый адрес наружу —
разделить на `bind()` и `run()` либо вернуть `SocketAddr` через канал.

Проверено по документации Tauri v2:

- `frontendDist` принимает URL, так что папка-заглушка не нужна; окно всё
  равно создаётся в `setup()` с `WebviewUrl::External`, когда порт уже
  известен;
- у capability есть поле `remote.urls` — страница, загруженная с
  `http://127.0.0.1`, может вызывать разрешённые команды Tauri. Это
  открывает нативные диалоги выбора папок без переписывания фронтенда.
  Оговорка документации про неотличимость iframe от окна касается Linux и
  Android — мы собираем мак и винду;
- обновление подписывается **собственной** парой ключей
  (`tauri signer generate`), платный сертификат для него не нужен;
  манифест — статический JSON, годится GitHub Releases;
- упаковщик умеет `nsis`/`msi` на винде и `app`/`dmg` на маке; для
  портабельного варианта берётся собранный exe без установщика.

## Настройки путей

Это отдельная часть работы, нужная независимо от окна, но без неё окно
бессмысленно: сейчас пути задаются аргументами командной строки.

**Где лежат данные.** База и миниатюры должны иметь три режима:

1. *Рядом с программой* — если каталог программы доступен на запись.
   Портабельный случай: флешка, папка «Программы» пользователя.
2. *В системной папке приложения* — `%LOCALAPPDATA%\photo-cleanup` на
   Windows, `~/Library/Application Support/photo-cleanup` на macOS.
3. *Выбранный вручную* — например, на большом диске, где лежит архив.

Выбор хранится в маленьком файле конфигурации рядом с программой (сам
путь к базе нельзя держать в базе). Смена пути требует перезапуска и
должна предлагать перенести существующие данные, а не бросать их.

**Папки архива.** Сейчас корни задаются в интерфейсе нашим собственным
браузером папок. С нативным диалогом (через `remote.urls`) это станет
привычным выбором каталога, но собственный браузер надо сохранить: он
единственный работает в docker-варианте, где каталоги примонтированы
внутрь контейнера.

**Экран настроек** должен показывать: где база, где миниатюры, сколько
они занимают, и кнопку «открыть эту папку» — на обеих системах.

## Фазы

### Фаза 1 — окно и пути (полтора-два дня)

- крейт `pc-desktop`, окно на внешний URL, сервер в фоновом потоке;
- порт `0`, адрес наружу из `pc-api`;
- три режима размещения данных, файл конфигурации, миграция данных при
  смене пути;
- иконки, имя окна, размер по умолчанию;
- сборка артефактов: `photo-cleanup-windows-x64.zip` с exe,
  `photo-cleanup-macos.zip` с `.app`.

Готово, когда: exe распаковывается в любую папку, запускается двойным
кликом, открывает окно, находит или создаёт базу, и всё это без консоли.

### Фаза 2 — поведение приложения (день)

- единственный экземпляр: второй запуск поднимает открытое окно, а не
  второй сервер;
- иконка в трее: открыть, остановить, выйти;
- запоминание размера и положения окна;
- на macOS — правильное поведение при закрытии окна (приложение живёт в
  доке);
- нативный диалог выбора папки через capability с `remote.urls`, с
  сохранением собственного браузера папок как запасного.

Готово, когда: закрытие окна не теряет работающую индексацию, повторный
запуск не плодит серверы, выбор папки открывает системный диалог.

### Фаза 3 — обновления (день)

- ключи `tauri signer generate`, приватный в секретах CI;
- публикация манифеста рядом с релизом;
- проверка обновлений с явного согласия и с возможностью отключить;
- на Windows установщик закрывает приложение сам — учесть в тексте.

Готово, когда: старая версия видит новую, обновляется и открывается с той
же базой.

### Фаза 4 — подпись и распространение (по деньгам, не по времени)

- **macOS**: без нотаризации скачанный `.app` Gatekeeper не запустит.
  Нужен Apple Developer Program (99 долларов в год), `codesign` и
  `notarytool` в CI. Пока не куплено — раздавать только zip с бинарём и
  честно писать, как обойти предупреждение.
- **Windows**: SmartScreen ругается на неподписанное, но запускает. Это
  ровно то же, что с нынешним zip, поэтому не блокер.
- `scoop` — самый дешёвый способ раздачи на винде, подпись не нужна;
  `winget` — заметнее, но хочет установщик.

## Риски и решения

| Риск | Что делаем |
|---|---|
| WebView2 отсутствует на старой Windows 10 | внятное сообщение со ссылкой; при желании — загрузчик в архиве |
| Порт занят, сервер не поднялся | порт `0` снимает проблему; ошибку показываем в окне, а не в консоли |
| Долгая задача при закрытии окна | окно закрывается в трей, задача продолжается; выход спрашивает подтверждение |
| Данные рядом с программой, каталог только на чтение | автоматический откат в системную папку с уведомлением |
| Расхождение десктопа и веб-интерфейса | интерфейс один и тот же, десктоп не имеет своих экранов |
| Забытая метка версии отрисовки в кэше | см. аудит: сделать её автоматической |

## Что проверять перед каждым релизом десктопа

1. Первый запуск на чистой машине: где создалась база, спросило ли о
   папках архива.
2. Портабельный запуск с флешки и из «Программ».
3. Перенос данных при смене каталога.
4. Индексация не прерывается при закрытии окна.
5. Обновление со старой версии сохраняет базу и настройки.
6. macOS: запуск на машине, где приложение скачано браузером.
